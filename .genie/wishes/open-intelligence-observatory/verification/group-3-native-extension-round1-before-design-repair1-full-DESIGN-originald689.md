## Approach

**PROPOSED composition:** one native qualification-control owner, two isolated native named-profile invocations (one restricted issuer identity per invocation), and only the read-only observatory evidence tools. The control owner is an explicitly patched native launcher/service, not an external substitute Harness constructor or proxy claiming native completion. Each host remains booted by supported `runProfile`/named profile plus frozen ordered patches. Brain stores accepted semantic evidence; the control store contains only identity bindings, stopped-admission generations, work obligations and currency reservations.

Per-principal ownership is deliberately preferred over adding broad multi-tenant storage semantics to the one-operator Web host: separate dedicated home/Session store/workspace/mount/IPC identities make foreign native records absent by construction. It does NOT eliminate issuer verification, cross-route checks, shared Brain-reader ACLs or runtime confinement proof. No operator login capability is exposed to the restricted principals. One principal can own two Sessions for active/queued/cold tests; stopping its domain closes admission for all its Sessions and independent descendants/forks, preventing new-ID bypass.

The native root owns dispatch arbitration and credential-bearing provider transport. Child profile processes have no provider credential or direct Internet route; their native adapters submit typed request/usage messages over a private instance-bound channel to the root. The root executes the pinned native DeepSeek transport, not a custom completion implementation. The same control owner brokers allowed evidence/tool dispatch so every actual work start and stop shares one serialization boundary. No generic HTTP CONNECT/tunnel endpoint exists. Root isolation denies every nonapproved origin/path/method, redirect and arbitrary worker/network tool. Internal control channels never become public Remote methods.

**Alternatives considered:** stock SDK lacks required chunks/cancel/history; stock Web cookies always admit the operator; archive-before-stop has a documented race/unawaited providers; a global `llm/stream` hook misses inner Messages/Files calls; separate plugin/socket cleanup misses launcher proxy disposal. A single shared multi-principal host would require ACL changes in many native storage owners and creates greater privacy risk. A complete future upstream-supported amendment could replace an equivalent patch after reviewed equivalence; alpha2 alone does not implement these contracts and is not selected or installed.

### Atomic stop and single-owner synchronization

**Required linearization point T:** root control transaction commits domain OPEN→STOPPED and increments generation while holding the same dispatch arbiter used for every actual model/file/tool/work initiation. No actual initiation with that domain occurs after T, even if a prompt, queue claim, pre-step or retry preparation happened before T. Work physically initiated before T is active and must be aborted/drained; provider computation already accepted cannot be retroactively erased or assumed refunded.

The root runs a single bounded control-event queue. Durable reserve commits before network initiation; preparation does not grant dispatch. After preparation the arbiter rechecks current identity/generation/stopped/budget, registers an obligation and persists `may_have_sent` before invoking the native send entry. This actual initiation executes synchronously under the arbiter, then the lock releases while asynchronous transport runs. Stop uses that same queue, so a stale prepared operation cannot initiate after commit. Native tool/evidence initiation follows the same sequence; child processes cannot dispatch around it. An append to the child inbox is not itself model/tool dispatch.

The stop transaction durably cancels queued operation intents and denies admission for the whole principal domain, including new Sessions and unrelated forks. The native prompt/create/resume/queue/controller/driver bindings check that domain before accepting a new intent; any pre-T inbox events remain historical but cannot dispatch later. No atomicity is invented between separate Session journal and control-store commits: intent IDs connect the two. A crash between control intent and native inbox receipt is unresolved/never-dispatched, not replayed automatically; recovery may reconcile readonly receipts, never duplicate a model call.

After T, root aborts active transport/evidence readers, cancels/drains AgentHandle owners and every registered queued/background/title/compaction/retry/tool obligation, flushes native Session writes and awaits write-handle closure where the runtime is being disposed. A Session-only stop may retain readonly controller/history; an Agent/plugin replacement first seals its owner, drains effects/Remote handles, then remounts readonly against the existing STOPPED generation. No archive/unarchive, reconnect or plugin reload clears STOPPED. Explicit future owner restart creates a new admitted generation; cancellation acceptance here requires no automatic restart.

A work registry is required by the present independent quiescence criterion, not a speculative scheduler. Owners register acquisition before publication, and record actual completion/abort/drain. Root quiescence succeeds only with no admitted/active/queued unclosed obligations, settled native handles, flushed storage and closed relevant transport readers. Missing owner, rejected disposer, detached nonsettling iterator, deadline or process kill yields distinct non-success/UNKNOWN. Deadline bounds waiting, not proof that work stopped.

### Durable control state, crash/recovery and GC

Use one embedded transactional SQLite control store owned by the native root, with exact [Node26.7.0 `node:sqlite` `DatabaseSync`](https://nodejs.org/download/release/v26.7.0/docs/api/sqlite.html) API (documentation read, not binary-executed). This avoids a new third-party driver. Latest-v26 docs actually resolved to26.11.1 and were NOT used to silently substitute its different `Database` API. Native driver stability is release-candidate; actual module availability, SQLite build/durability and filesystem behavior require future qualification at the pinned executable.

Durable records are limited to: root run/instance/issuer bindings; domain generation and STOPPED tombstone; admitted intent/obligation references and terminal outcome; immutable tariff/cap revision; attempt reservation/send-uncertainty/usage/cost; launcher completion sequence. No raw key, prompt/body/tool result/financial claim is copied into it. Native Sessions retain prompt/history/cursor; Brain retains semantic evidence. References link authorities without asserting a cross-database transaction.

Root is the sole application writer; a pinned private IPC socket and exclusive instance supervisor prevent concurrent launchers. SQLite `BEGIN IMMEDIATE` plus verified `synchronous=FULL`/journal policy gives transactional updates; durable checkpoint/fsync failure denies startup and dispatch. Socket liveness/instance ownership must be proven before reclaim; never infer stale from PID absence alone. Root startup checks schema/version/integrity, frozen owner/tuple/volume identity and all uncertain obligations before exposing tenant admission.

Crash after reserve/before physical send keeps reserved funds unless root proves `never_sent`; crash after `may_have_sent` retains full reserve and blocks later paid admission. STOPPED tombstones survive crash; live OPEN domains become recovery-held until all child processes/transport obligations are independently settled, preventing automatic resume. Missing/corrupt control file, disappeared persistent volume or unknown schema is fail-closed; never create an empty replacement and restore spending/admission. Native history may be read under authenticated scope even while dispatch stays held.

### Launcher outcomes and independent witness

The actual profile launcher already owns app fiber and proxy disposer; patch that owner rather than installing a second proxy.
