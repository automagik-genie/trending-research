F7. Current SSE terminal-usage shape [source claim; high confidence]
`stream` sends data-only SSE partial deltas and terminates with `data: [DONE]`. `stream_options` requires `stream:true`, otherwise HTTP400. Exact `include_usage` semantics: when true, all chunks have a `usage` field, null except last; omitted/false, usage is absent except last. “Either way, the last chunk before the data: [DONE] message carries the token usage statistics for the entire request in its usage field.” “No separate usage-only chunk is emitted”; the statistics are on the last content chunk, whose choices array “always contains exactly one element that carries no new content and a non-null finish_reason.” Thus a successful full stream's usage is not conditional on enabling include_usage, and an empty-choices usage-only parser is not what this document specifies. No delivery/cost guarantee for a disconnected stream follows from the normal terminal shape. Source: https://api-docs.deepseek.com/api/create-chat-completion [retrievedUTC 2026-10-09T17:47:06Z–17:47:15Z].

F8. Interruption and other finish reasons [source claim; high confidence]
Published enum: `stop`, `length`, `content_filter`, `tool_calls`, `insufficient_system_resource`, `aborted`. `length` means request max tokens reached; insufficient_system_resource means interrupted by insufficient inference-system resources; aborted means generation interrupted. Neither the enum nor general terminal usage documentation states the fee/refund policy for these outcomes, continued generation after client disconnect, or guaranteed usage delivery when transport fails. Source: https://api-docs.deepseek.com/api/create-chat-completion [retrievedUTC 2026-10-09T17:47:06Z–17:47:15Z].

F9. Account-level concurrency and request lifetime [source claim; high confidence]
Concurrency: Flash 2500; Pro 500. Exact rules: “A request counts as one concurrent connection from the time it is sent until the model response is complete”; limits are account-level “regardless of which API Key is used”; excess yields HTTP429. Regular users' user_id values are combined for concurrency; increased-quota accounts have account plus per-user_id limits (Flash2500, Pro500, empty ID treated specially). During waiting, non-streaming can return empty lines and streaming SSE comments `: keep-alive`. Exact timeout: “If the request has not started inference after 10 minutes, the server will close the connection.” This is a pre-inference waiting cutoff, not a documented 10-minute maximum inference duration or spend limit. No numeric RPM/TPM, retry count, retry/backoff schedule, Retry-After semantics, idempotency guarantee, or billable-error exemption is specified in this rate-limit body. Sources: https://api-docs.deepseek.com/quick_start/rate_limit [retrievedUTC 2026-10-09T17:47:06Z–17:47:15Z]; matching table: https://api-docs.deepseek.com/quick_start/pricing [retrievedUTC 2026-10-09T17:47:06Z–17:47:41Z].
